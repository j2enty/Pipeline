# 인터뷰 7구간 상세 가이드

> Step 4 (사용자 인터뷰)의 7구간 질문 문구·출처(Heilmeier Catechism 등)·산출 매핑 상세.
> 이슈 본문을 먼저 읽고 각 구간의 답이 충분한지 판단한 뒤 질문을 선택적으로 수행한다.
> **질문은 하나씩 — 이전 질문 완전 종결 후 다음으로.**

## 모드 결정

- **기본 모드**: 각 구간 답이 이슈에 이미 있으면 스킵 (단 **4번·5번은 반드시 물어본다**)
- **`--deep` 모드**: 모든 구간 스킵 없이 + 꼬리질문 강화
- **`--bot` 모드**: AskUserQuestion 없이 이슈 본문에서 자동 추론, 미확정 항목은 전부 "○○로 가정함 ← 맞나요?" 형식으로 표시

## 인터뷰 7구간

**1. 뭘 만들려는 거예요? (한 문장, 전문용어 빼고)**
← Heilmeier Catechism
- 이슈 본문에 이미 명확하면 스킵 (`--deep` 시 스킵 금지)
- 답이 흐리면: "왜 필요해요?" → "왜요?" 순서로 캐물음 (5 Whys — 뻔함 방지)
- 산출 → 사람용 "한 줄" 섹션 초안

**2. 지금은 어떻게 하고 있고, 뭐가 불편해요?**
← Heilmeier
- 이슈 본문에 이미 있으면 스킵 (`--deep` 시 스킵 금지)
- 산출 → ② AI용 명세의 배경 자료 (사람용에는 별도 섹션 없음 — "한 줄" 맥락으로 반영)

**3. 누가 써요? 성공하면 뭐가 달라져요?**
← Heilmeier (성공 기준)
- 이슈 본문에 이미 있으면 스킵 (`--deep` 시 스킵 금지)
- 산출 → 사람용 "키 피처" 섹션

**3.5 이거 만드는 방법이 여러 개일 텐데, 생각해둔 방식 있어요?** [신설 — 약점2]
← 접근법 노출 (AI가 구현 방식을 임의 선택하고 사실인 척 박는 것 차단)
- 없다고 하면: AI가 후보 2~3개 제시 + "○○ 방식으로 갈게요 ← 맞나요?"
- 이슈 본문에 이미 있으면 스킵 (`--deep` 시 스킵 금지)
- 산출 → 사람용 "★ 결정할 것" — 접근법 항목

**4. 이번엔 뭘 '안' 해요? 다음으로 미루는 건?** ← **스킵 금지**
← MoSCoW "Won't" (경계 — 이슈에 거의 적혀 있지 않음, 거의 항상 물어라)
- 이슈에 있어도 반드시 물어본다 (`--bot` 모드: AskUserQuestion 대신 AI가 추론 후 "○○로 가정함 ← 맞나요?"로 표시)
- 산출 → 사람용 "이번에 안 하는 것" 섹션

**5. 표준 제약 확인 (AI가 먼저 깔고 확인받기)** ← **스킵 금지**
← AI 선제 가정 (비전문 운영자가 "딱히요"로 빈칸이 되는 경로 차단)
- ❌ "보안·성능·제약 있어요?" 식 열린 질문 금지
- AI가 먼저 제시한다:
  ```
  "보통 이런 기능은
   · 인증: ___
   · rate-limit: ___
   · 입력검증: ___
   으로 갑니다. 이대로 가정할게요 ← 맞나요?"
  ```
- 이슈에 있어도 반드시 물어본다 (`--bot` 모드: AskUserQuestion 대신 AI가 추론 후 제약 항목을 "○○로 가정함 ← 맞나요?"로 표시)
- 산출 → 사람용 "★ 결정할 것" — AI 가정 항목들

**6. 제일 위험한 게 뭐예요? 아직 모르는 건요?**
← Heilmeier (리스크)
- 이슈 본문에 이미 있으면 스킵 (`--deep` 시 스킵 금지)
- 산출 → 사람용 "리스크 / 미정" 섹션

**7. "이미 출시했다 치고" 한 줄로 말하면?**
← Working Backwards
- 이슈 본문에 이미 있으면 스킵 (`--deep` 시 스킵 금지)
- 산출 → 사람용 "한 줄" 섹션 확정

## 인터뷰 후 추가 확인 (AskUserQuestion)

1. **영역 확인** — 이 기능이 건드릴 영역은?
   - multiSelect: Backend / Admin / Frontend / iOS / Android / Design
   - Claude가 이슈 본문 읽고 선제안 → 사용자가 조정
   - **Frontend (사용자 공개 웹, Next.js)는 미래 도입 영역** — 도입 전이면 multiSelect에서 자동 제외 또는 사용자가 명시적으로 선택할 때만 포함

2. **slug 확인** — 제안된 `<slug>`가 괜찮은가? (파일명·브랜치명은 `<parent-N>-<slug>` 형식이 됩니다)
   - options: "OK" / "다른 이름" (다른 이름 고르면 순수 slug만 재입력)
