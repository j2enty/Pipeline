# contract.md 템플릿 — 영역 간 공유 계약 (SSOT)

> Step ②b 에서 작성한 계약을 Step 6a 에서 `plans/<parent-N>-<slug>-contract.md` 로 저장할 때 쓰는 템플릿이다.
> `<parent-N>`·`<slug>` 는 실행 시점 값으로 채운다.

````markdown
# [contract] <parent-N>-<slug> — 영역 간 공유 계약 (SSOT)

> 이 문서는 2개 이상 영역이 만나는 지점의 **단일 진실원(SSOT)**이다.
> 각 영역 명세(`-backend.md`·`-admin.md` 등)는 여기를 **참조만** 하고 다시 정의하지 않는다.
> 표기·타입·규약이 어긋나면(snake/camel 등) 이 문서가 정답.

## API 스키마
{영역 간 주고받는 엔드포인트별 요청/응답 — 필드명·타입·예시. 표기 규약 하나로 통일.}

## 데이터 모델
{영역 간 공유되는 엔티티·DTO 구조.}

## 이벤트 / 메시지 (해당 시)
{영역 간 비동기 통신이 있으면 — 이벤트명·페이로드. 없으면 "해당 없음".}

## 공통 규약
- 표기: {응답 JSON 필드를 snake_case / camelCase 중 무엇으로 통일하는지 + 어느 영역에서 변환하는지}
- 시각: {예: ISO 8601 UTC}
- 에러 응답 형태: {공통 에러 스키마}
- 인증: {토큰 전달 방식 — 해당 시}

## 이 계약을 참조하는 영역
- {backend / admin / frontend ... — 이 계약을 구현·소비하는 영역 목록}
````

> **편집 기준**: 계약에는 **영역이 실제로 만나는 지점만** 넣는다. 한 영역 내부 구현 디테일은 그 영역 명세(②c)로 내린다.
> **표기 규약은 반드시 하나로 통일**하고 어느 영역이 변환 책임을 지는지 명시한다(snake/camel 표류의 근본 차단).
