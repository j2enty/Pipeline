# 사람용 기획서 템플릿 (§3.6)

> Step 6a 에서 `Docs/claude/requirements/<parent-N>-<slug>.md` (사람용 기획서 — 운영자가 GO/수정 판단하는 문서)를 작성할 때 쓰는 템플릿이다.
> `<parent-N>`·`<slug>`·`<parent-issue-title>` 는 실행 시점 값으로 채운다.

```markdown
# <parent-N>-<slug> <parent-issue-title>

## 한 줄
{무엇을·왜 — "아 이거구나"가 한 문장에}

## 당신이 결정할 것  (★ = 되돌리기 비쌈)
- ★ 접근법: {인터뷰 3.5번 결과 — 선택한 방식 또는 "○○ 방식으로 가정함 ← 맞나요?"}
- ★ {기타 보안·아키텍처·출범급 결정}
- {AI 가정}: "○○로 가정함 ← 맞나요?"    ← 인터뷰 5번 제약 가정 항목들

## 이번에 안 하는 것 (경계)
- {인터뷰 4번 — 다음으로 미루는 것·scope 밖}

## 키 피처
- {인터뷰 3번 — 핵심 기능·성공 기준}

## 리스크 / 미정 (구멍)
- {인터뷰 6번 — 안 정해진 것·노출·한계}

## 상세 명세 → plans/<parent-N>-<slug>-*.md  (AI용, 안 봐도 됨)
```

> **편집 기준**: "이 정보가 운영자의 GO/수정 판단을 바꾸는가?" — 아니면 뺀다. 구현 디테일·자명한 것은 AI용 plans/로 내린다.
> **가정+표시**: AI가 인터뷰 답 없이 채운 항목은 반드시 "○○로 가정함 ← 맞나요?"로 `결정할 것` 섹션에 노출 (조용한 기정사실화 차단).
